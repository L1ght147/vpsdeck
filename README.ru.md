# vpsdeck

[English](README.md) · **Русский**

Мониторинг ваших VPS через Telegram-бота.

- **Алерты**, когда сервер пропал, заканчивается место на диске или CPU / RAM долго под нагрузкой, и когда всё пришло в норму.
- **Карточки серверов** в чате: диски, CPU, RAM, нагрузка, аптайм, обновления, нужна ли перезагрузка.
- **Ставится почти на любой сервер**: один бинарник, без веб-сервера, домена и Docker. Не трогает nginx, Caddy и всё, что уже работает.
- Русский и английский язык.

```
[агент] [агент] [агент] ──HTTPS, раз в 60 с──▶ [хаб] ──▶ Telegram-бот
```

**Агент** стоит на каждом сервере, собирает метрики и отправляет их на хаб. Он не открывает портов и работает от непривилегированного пользователя.
**Хаб** стоит на одном сервере: хранит последние отчёты (SQLite), отправляет алерты и работает как бот. Он слушает один TCP-порт на ваш выбор (по умолчанию `8443`) со своим самоподписанным сертификатом. Агенты проверяют этот сертификат по отпечатку, поэтому связь зашифрована и подменить хаб нельзя — домен не нужен.

## Что отслеживается

| Метрика | Алерт |
| --- | --- |
| Онлайн / офлайн | нет отчёта 3 мин → офлайн, и «снова на связи» |
| Место на каждом разделе (+ inode) | ≥ 85 % предупреждение, ≥ 95 % критично |
| CPU, RAM, swap, load average | CPU или RAM ≥ 90 % дольше 10 мин |
| Обновления apt, security-обновления | ежедневная сводка |
| Нужна перезагрузка | ежедневная сводка |

Алерты приходят только при смене состояния. Сервер можно заглушить на 1 ч или 24 ч.

## Требования

- Linux с systemd, amd64 или arm64. Обновления проверяются через apt (Ubuntu, Debian); на других системах работают только метрики.
- Для хаба: бот от [@BotFather](https://t.me/BotFather) и один свободный TCP-порт, доступный с других ваших серверов.

## Установка

### 1. Хаб (один раз, на любой сервер)

```bash
curl -fsSL https://raw.githubusercontent.com/L1ght147/vpsdeck/main/scripts/install.sh | sudo bash
```

Выберите язык, затем **Установить хаб**. Установщик спросит:

- токен бота от @BotFather;
- ваш Telegram ID (его покажет [@userinfobot](https://t.me/userinfobot));
- порт для агентов (предложит свободный, по умолчанию `8443`);
- адрес, по которому агенты найдут сервер — публичный IP определится сам.

Он откроет порт в ufw / firewalld, если они включены (в файрволе хостера откройте порт сами), запустит хаб и предложит поставить агента на этот же сервер. Бот пришлёт «Хаб запущен».

### 2. Агенты (на каждый сервер)

Откройте бота, нажмите **Добавить сервер** и отправьте имя, например `web-1`. Бот ответит командой в одну строку — выполните её на сервере:

```bash
curl -fsSL https://raw.githubusercontent.com/L1ght147/vpsdeck/main/scripts/install.sh | sudo bash -s -- agent --url https://203.0.113.5:8443 --token <TOKEN> --name web-1 --lang ru --fingerprint <FINGERPRINT>
```

Установщик сначала отправит тестовый отчёт, так что неверный адрес, токен или закрытый порт видно сразу. Сервер появится в боте в течение минуты.

### Обновление, удаление, статус

Раз в сутки хаб проверяет наличие нового релиза на GitHub и при его появлении присылает уведомление в бот. Бот обновления не устанавливает.

Запустите установщик снова и выберите **Обновить**, **Удалить** или **Статус**, либо сразу:

```bash
curl -fsSL https://raw.githubusercontent.com/L1ght147/vpsdeck/main/scripts/install.sh | sudo bash -s -- update
```

## Бот

У бота одна команда — `/start`, она открывает главное меню. Всё остальное — инлайн-кнопки:

- **Серверы** — список со статусом и заполненностью диска; карточка сервера (CPU, RAM, диски, обновления) с кнопками «Обновить», «Пакеты», «Заглушить», «Удалить».
- **Требуют внимания** — серверы, которые не в сети, ожидают подключения или превысили пороги, с указанием причин.
- **Обновления** — серверы с обновлениями и списки пакетов.
- **Добавить сервер** — отправьте имя (или выберите имя по умолчанию) и получите команду установки.
- **Настройки** — язык и текущие пороги алертов.

Ботом могут пользоваться только Telegram ID из списка `admins`.

## Настройка

`/etc/vpsdeck/hub.yaml` (после правки: `systemctl restart vpsdeck-hub`):

```yaml
listen: ":8443"
public_url: "https://203.0.113.5:8443"   # адрес, на который ходят агенты
bot_token: "123456:ABC..."
admins: [123456789]                      # можно несколько ID
lang: ru                                 # en | ru
db_path: /var/lib/vpsdeck/hub.db
digest_time: "09:00"                     # ежедневная сводка обновлений
timezone: "Europe/Moscow"
thresholds:
  disk_warn: 85
  disk_crit: 95
  cpu: 90
  mem: 90
  sustain: 10m                           # сколько CPU/RAM должны держаться высоко
  offline_after: 3m
# tls_disable: true                      # только если хаб стоит за вашим HTTPS-прокси
# disable_update_check: true             # не проверять новые релизы на GitHub
```

`/etc/vpsdeck/agent.yaml`:

```yaml
hub_url: "https://203.0.113.5:8443"
token: "..."
fingerprint: "..."     # SHA-256 сертификата хаба; его выводит `vpsdeck hub fingerprint`
name: "web-1"
interval: 60s
update_interval: 1h
```

Агент сам не запускает `apt update`: Ubuntu и Debian обновляют списки пакетов сами (`apt-daily.timer`).

## Безопасность

- Агенты только делают исходящие HTTPS-запросы, на них ничего не слушает.
- Сертификат хаба создаётся при первом запуске, каждый агент проверяет его по отпечатку.
- У каждого сервера свой токен; хаб хранит только его SHA-256. Удаление сервера отзывает токен.
- Установщик сверяет загрузки с `checksums.txt`. Сервисы работают от пользователя `vpsdeck` с песочницей systemd.

## Разработка

```bash
go test ./...
go run ./cmd/vpsdeck agent -print     # показать отчёт с этой машины
go run ./cmd/vpsdeck hub -dev         # хаб на 127.0.0.1:8080 по HTTP, без бота
```

Релиз: запушьте тег `vX.Y.Z`, GitHub Actions соберёт linux/amd64 и linux/arm64 через GoReleaser.
